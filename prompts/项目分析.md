## Role
你是一名资深的解决方案架构师和技术文档专家。

## Context
分析整个项目的代码

## Task
请深度扫描并分析该项目，**不要只给出一份大报告**，而是必须生成 **3份独立的 Markdown 文档**，分别从架构、流程和运维视角进行总结。

## Detailed Requirements

### 文档 1: 项目技术架构文档 (ARCHITECTURE.md)
- **技术栈**：列出后端框架、前端框架、数据库、中间件、第三方API。
- **分层架构**：描述 Controller/Handler -> Service -> Repository/DAO -> Model 的调用关系。
- **模块划分**：画出模块间的依赖关系（使用 Mermaid 语法）。
- **核心数据结构**：主要的实体关系图（ER 图）或核心 DTO 定义。

### 文档 2: 核心业务流程图与数据流 (FLOW.md)
- **整体流程图**：使用 Mermaid sequenceDiagram 或 flowchart，描述从“用户请求入口”到“返回响应”的全链路。
- **关键子流程**：识别项目中最重要功能，分别画出其活动图。

### 文档 3: 项目总结与开发指南 (SUMMARY.md)
- **项目定位**：一句话说清楚这个项目是干什么的。
- **快速启动**：基于项目中的配置（如 docker-compose, package.json, requirements.txt），给出本地运行的具体命令。
- **目录结构与职责**：解释项目中每个一级文件夹的用途。
- **待办/风险点**：分析代码中存在的潜在性能瓶颈、安全漏洞或 TODO/FIXME 注释。

## Constraints
1. **必须使用 Mermaid** 绘制所有流程图和架构图，不要使用 ASCII 图。
2. **零上下文遗漏**：如果项目中没有 README，请根据代码推断；如果找不到某些依赖，请标记“[推测]”。
3. **独立文件**：在回答中，请直接输出三个代码块（标注为 markdown），每个代码块对应一个文件的内容，且文件开头必须有标题和简介。
4. **深入代码细节**：不要只读文件夹名，必须读取关键文件（如 main.go, app.py, index.js, pom.xml 等）来确认逻辑。
